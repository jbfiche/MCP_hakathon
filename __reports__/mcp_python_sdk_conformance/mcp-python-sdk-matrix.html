Read this before you build on it

The eight things most likely to bite a hackathon build, pulled out of the full matrix below.
Long-running / async tool execution (Tasks extension) is not implemented The SDK's own source comments confirm task types are defined for 2025-11-25 but every tasks/* method is deliberately excluded — no wire handlers, no transport plumbing. If your demo needs a tool that runs longer than one request, this SDK gives you nothing built-in for it.
Token storage is a bare interface, not a secure implementation The spec says clients/servers MUST store tokens securely. The SDK ships only a TokenStorage protocol plus an explicitly non-persistent InMemoryTokenStorage example — real storage is on you.
Security Best Practices doc has no confirmed code-level enforcement Confused-deputy consent, token-passthrough guarding, open-redirect exact-matching, and OAuth-URL scheme allowlisting: none turned up a named class or function in either research pass. Treat these as your responsibility, not the SDK's, until proven otherwise.
Client ID Metadata Documents (CIMD) only work on the client side CIMD is the spec's new preferred client-registration method. The Python SDK supports it as an OAuth client, but the auth-server-side routes only speak the old Dynamic Client Registration — there is no fetch-and-validate path for a client-supplied metadata URL.
Two code paths disagree on the default protocol version ClientSession.initialize() always offers 2025-11-25, while the docs describe the high-level Client as defaulting to 2026-07-28. Plausibly two intentional eras of the same SDK — but unresolved from docs alone. Verify directly before depending on either default.
Newer auth mitigations (RFC 9207 iss check, exact redirect-URI match) are unverified No code evidence surfaced either way for the mix-up-attack mitigation or strict redirect-URI validation added by this revision. Don't assume coverage just because older OAuth mechanics are solid.
Sampling and Roots are themselves deprecated by this spec revision Both still work (for talking to pre-2026 servers) but SEP-2577 marks them deprecated in favor of calling an LLM API directly or passing paths through tool params. Don't build new functionality on top of either.
Ping and JSON-RPC batching being absent is correct, not a gap Both were removed from the spec itself (ping outright, batching since 2025-06-18). The SDK not implementing them is conformance, not a shortfall.

Methodology. Five parallel research agents each fetched the live spec pages under modelcontextprotocol.io/specification/2026-07-28 for one domain, then cross-checked every requirement they found against the Python SDK v2 source and docs surfaced through the context7 documentation index for modelcontextprotocol/python-sdk. “Full” means direct code or first-party-doc evidence was found; “Partial” means evidence covered one side of a two-sided requirement (e.g. client but not server) or was doc-asserted without a matching code snippet; “Unknown” means no evidence turned up either way — treated as absence of evidence, not evidence of absence; “N/A” marks a feature the spec itself removed, where the SDK correctly implements nothing. Self-reported SDK claims (READMEs, roadmaps) were deliberately weighed against actual code, not taken at face value. This pass covers the Python SDK only; the Rust SDK was excluded at the user’s request.
